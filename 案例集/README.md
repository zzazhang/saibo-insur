# 网络安全保险理赔案例集

每个案例按「事故描述 → 条款责任对应 → 理赔计算」三步展开，全部数字由理赔核算器
算出，可复现：

```bash
cd 理赔核算器
python -m claims_calc.cli run cases/*.json --md ../案例集/案例报告 --summary ../案例集/案例总览.md
python -m claims_calc.cli mapping <保单id> --out ../案例集/条款责任对应表/<保单id>.md
python -m claims_calc.cli compare cases/<案例>.json --policies <id1>,<id2>
```

## 目录

| 路径 | 内容 |
| --- | --- |
| `理赔核算器/cases/*.json` | 案例源文件（唯一事实来源，含案情叙述与全部参数） |
| `案例集/案例报告/` | 自动生成的案例报告与结果 JSON |
| `案例集/条款责任对应表/` | 各保单的 69 项完整责任映射 |
| `案例集/案例总览.md` | 全部案例的赔付率对照 |

案例报告与对应表均为**生成物，不要手工编辑**——改案例源文件后重跑即可。

## 三层口径

| 层 | 回答什么 | 结论含义 |
| --- | --- | --- |
| ① 事实口径核定损失 | 事故造成了多少损失 | 风险敞口有多大 |
| ② 承保过滤计入金额 | 哪些属于这张保单管的事 | 少赔 = **买错了产品** |
| ③ 保单结算赔付额 | 实际能拿到多少钱 | 少赔 = **保额买少了** |

②③ 是两个不同的结论，不能混为一谈。

## 已完成案例摘要

### C8 / C8B — 勒索软件（中远海运）

A公司（区域性冷链物流企业）遭勒索软件加密调度与仓储系统，中断 5 天。

| 口径 | C8（未付赎金） | C8B（反事实：付了 60 万） |
| --- | ---: | ---: |
| ① 事实口径核定损失 | 2,714,200 | 3,314,200 |
| ② 承保过滤计入金额 | 1,265,200 | 1,265,200 |
| ③ 保单结算赔付额 | 1,040,000 | 1,040,000 |
| 赔付率 | 38.3% | 31.4% |

**多损失 60 万，赔付额一分不变。** 这是本项目「名义承保 ≠ 实际保障」论点的量化落点：
条款第八条第一款明文承保赎金、第十二条为其设了独立分项限额、第二十六条索赔材料里
直接写了「勒索金支付记录」——文本上是一项配置完整的保障。但第二十三条同时要求
「涉及网络勒索须立即向公安部门报案」，且索赔时须同时提交报案回执与支付记录。
这两份材料在国内实践中难以同时合法取得，条款自身即构成闭环障碍。

另外两点结构性发现：

- **营业中断 113.4 万元完全不获赔**，且不是限额或免赔额问题——本保单条款中根本
  没有营业中断责任项。这是产品定位问题（服务给付型应急响应险，非损失补偿型财产险），
  只有第②层能揭示，第③层看不出来。
- **条件免赔额被触发**：上一年度安全检测已将 RDP 公网暴露列为高危且未整改，
  符合第四条，免赔额由 10 万上浮 10% 至 11 万。这类把投保人安全治理义务货币化的
  设计在国内产品中少见，值得在定价模型中单列。

### 同一事故 · 五款保单对照

| 投保产品 | 计入金额 | 赔付额 | 赔付率 |
| --- | ---: | ---: | ---: |
| 平安 B 款 | 2,629,200 | 2,234,000 | 82.3% |
| 泰康在线 | 2,429,200 | 2,229,200 | 82.1% |
| 苏黎世中国 2020 | 2,429,200 | 2,029,200 | 74.8% |
| 中远海运 应急响应 | 1,265,200 | 1,040,000 | 38.3% |
| 珠峰财产 检测与修复 | 683,200 | 490,000 | 18.1% |

完全相同的事故事实，赔付率从 18.1% 到 82.3%，相差四倍以上。差异全部可追溯到具体
条款差异，无一处来自参数调整。

> **参数假设声明**：责任映射严格依据各产品公开条款的分析文件；但结算参数
> （分项限额、免赔额、累计限额）全部为演示用假设值——条款原文对这些数值的表述
> 普遍为「由投保人与保险人协商确定」，并无公开数字。引用任何赔付率时必须一并
> 标明该假设。
